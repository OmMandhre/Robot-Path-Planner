About Smart Warehouse Robot

Project Overview

Smart Warehouse Robot is an educational AI path-planning simulator developed for computer engineering students. It simulates an autonomous mobile warehouse robot navigating a 2D floor grid while avoiding obstacles and storage shelves.

Key Educational Objectives

  • Demonstrate classical AI search algorithms (uninformed vs. informed).
  • Visualize robot navigation and path wavefronts in real time.
  • Empirically benchmark and compare algorithm performance.
  • Understand the role and mathematical admissibility of heuristics in discrete grid search.

Technology Stack

Python 3 AI search engines using deque and heapq.
Flask REST API routes for pathfinding and benchmarking.
HTML5 Semantic page structure and accessible layout.
CSS3 High-contrast WCAG AA responsive design.
Vanilla JS Fetch API communication and grid animations.

How to Use (8-Step Guide)

  1. Select a warehouse grid size (4×4, 5×5, 6×6, or 10×10).
  2. Choose a map preset or draw a custom floor plan.
  3. Set the robot start (S) and destination goal (G).
  4. Place obstacles (blocked walls) and shelves (items).
  5. Choose an AI search algorithm and distance heuristic.
  6. Click "Find Path" to execute the algorithm in Python.
  7. View explored nodes, the final route, and performance metrics.
  8. Click "Compare All Algorithms" to compare empirical results side-by-side.
Scope & Limitations: This application is a software simulation, not a physical hardware controller. Execution times in milliseconds vary according to local computer specs and thread load.

AI Search Theory & Viva Voce Guide

1. Breadth-First Search (BFS)

Concept: Explores level-by-level outward from start.

Frontier: FIFO Queue (collections.deque)

Optimality: Guaranteed shortest path on unweighted grid.

Complexity: Time: O(V + E), Space: O(V)

2. Depth-First Search (DFS)

Concept: Explores deeply along one branch before backtracking.

Frontier: LIFO Stack (Python list pop())

Optimality: Not guaranteed (frequently finds non-optimal detours).

Complexity: Time: O(V + E), Space: O(V)

3. Greedy Best-First Search

Concept: Prioritizes nodes closest to destination using h(n).

Frontier: Priority Queue (heapq sorted by h(n))

Optimality: Not guaranteed (can be misled by obstacles).

Evaluation: f(n) = h(n)

4. A* Search (A Star)

Concept: Combines past cost g(n) with estimated remaining cost h(n).

Frontier: Priority Queue (heapq sorted by f(n))

Optimality: Guaranteed optimal with admissible heuristic.

Formula: f(n) = g(n) + h(n)

f(n) = g(n) + h(n)

g(n) = actual cost from start to cell n.  |  h(n) = estimated heuristic cost to goal.

Manhattan Distance: h(n) = |r - r_goal| + |c - c_goal|

Exact minimum orthogonal moves on 4-directional grids without diagonal steps (admissible and consistent).

Algorithm Comparison Summary

Algorithm Data Structure Shortest Path Guaranteed? Main Idea
BFS Queue Yes (unweighted grid) Explore level by level
DFS Stack No Explore deeply, then backtrack
Greedy Best-First Priority queue No Move toward the estimated goal
A* Priority queue Yes (under appropriate conditions) Combine actual and estimated cost
